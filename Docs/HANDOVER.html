1. Em uma frase

xpan (projeto Daniel Augusto v2) é um ERP SaaS multi-tenant para redes de padaria/confeitaria com uma fábrica central + N lojas: pedidos D+X, cronograma de produção, execução no chão, expedição/entrega e ocorrências — sem PDV fiscal nem financeiro.

4. Como rodar local + envs

Install / scripts

cp .env.local.example .env.local   # preencher URL + anon key + CRON_SECRET
npm install
npm run dev                        # http://localhost:3000
npm run build && npm start
npm test                           # tsx --test "src/**/*.test.ts"
npm run lint

Scripts Supabase úteis: supabase:gen-types, supabase:seed:*, supabase:auth:bootstrap, supabase:master:bootstrap, supabase:remote:status. Docker Compose dedicado não está no root — banco via projeto Supabase (local CLI ou cloud). a confirmar se o time usa supabase start no dia a dia.

Golden path

Loja pediu (D+X)
  → Cronograma / motor (schedule + snapshots)
  → Liberação (manual ou auto-release 18:00 BRT)
  → OP no chão (drop antes/depois forno, batidas)
  → Expedição (checklist por loja)
  → Entrega / tentativas
  ↔ Ocorrências (loja → fábrica)

6. Dados / domínio analítico crítico

  • Motor: src/lib/factory-planning/engine.ts — lead days, gaps por produto, disponibilidade, snapshots, expansão MPI.
  • Snapshots: pedidos/itens congelam fatores e (pós-jul/2026) receita na liberação; edição viva não deve “vazar” para OP já liberada.
  • Códigos de negócio: sequências em BRT (America/Sao_Paulo) — bug UTC corrigido em jul/2026.
  • Receita por etapa: enum stage (esponja→…→montagem); capacidade de batida pelo maior recipiente, não soma total da ficha.
  • Métricas gestor: lead time, OTIF, ocupação, falhas (factory-metrics).
  • Riscos de dado abertos (vault): D01 RLS sem role em 2 tabelas; D02 list_profile_labels cross-tenant; D03 sem UNIQUE anti-duplicidade de pedido.
